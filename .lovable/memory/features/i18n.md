Custom lightweight i18n (no i18next). Engine: `src/i18n/index.tsx`, languages in `src/i18n/config.ts`.

Supported: en (bundled fallback), es (neutral LATAM), pt (Brazilian), fil (natural Taglish), hi (simple conversational Hindi, no heavy Sanskritized words), id, fr (tutoiement). Non-English packs are lazy chunks — keeps cold start/ANR profile intact.

Layout:
- Base packs (common, nav, share, settings): `src/i18n/locales/<lang>.ts`
- Per-screen packs: `src/i18n/screens/<screen>/<lang>.ts` (auto-merged via `import.meta.glob`; English screen packs are eager). Add a new screen by creating the folder with all 7 language files.
- Every non-English file must match its `en.ts` sibling key-for-key with identical `{{placeholders}}`.

Usage: components `const { t } = useT()` from `@/i18n`; helpers/modules import `t` directly. Never resolve translations at module scope (language switches at runtime — this broke `DailyPermissionNudge`'s THEMES object once). Never shadow `t` with a map/loop variable (`const t = THEMES[k]`, `.map((t) => …)` both caused build breaks).

Copy rules: keep "Prayly", "Premium", "PRO", "Live" untranslated; never "Velora"; never "Watch ad to unlock" phrasing; CTAs stay short (badge/button widths). Translations must read native, not machine-translated.

Status: UI localization COMPLETE (~1023 screen keys + base pack, 13 screen packs, all 7 languages at parity). Packs: today, onboarding, premium, quiz, journeys, dailyverse, devotional, companion, favorites, wallpapers, parallax, prayer, overlays. Wired across all pages/components except intentionally skipped: admin pages, DebugLogs, AlarmPreview/NotificationPreview, PrivacyPolicy/TermsOfService (legal text stays English). Remaining future work is content localization (verses, journeys, prayers, quiz questions), not UI.
